# OE-361 F follow-on — optional `locality` on customer detail

Work snapshot. Durable: [customer-detail-locality.md](../requirements/customer-detail-locality.md).

Retailer customer detail already exposes notes / credit / identity. It omitted optional locality. No customer, mapping, profile, or address model on this stack has a `locality` column — do not invent one. This slice only echoes `locality` on detail when the attribute exists; otherwise `null`.

Customer list is a hot path and is contested by OE-305. Do not add `locality` there.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Customer detail includes optional `locality` | Notes / credit / identity only | **EXTEND** — `getattr(..., 'locality', None)` |
| Missing field / null stays null | n/a | same (`null` / `""` passthrough) |
| No address query when field missing | n/a | detail does not read `customer_address` |
| List serializer | Existing / contested OE-305 | unchanged — no `locality` |
| Auth/tenancy | Shop-scoped detail | unchanged |

## Done in this change (EXTEND, one slice)

- `RetailerCustomerDetailSerializer` exposes optional `locality`
- Detail view passes `resolve_customer_detail_locality` (no address query unless a model declares the field)
- Tests: helper missing/echo/passthrough, serializer present/null/empty, list drops undeclared locality, HTTP detail null + no address query, list omits key, 401/403, shop-scoped mappings

Out of scope: list serializer (OE-305), address migration, wishlist (OE-343), CRM write, FE, timeline/OFD/khata/UPI/slots, inventory.adjust, pack write, merge, Jira Done, live `*.ordereasy.win`.
