# OE-103 F-0021 — Parent-child pack SKUs (thin slice)

Work snapshot. Durable: [parent-child-pack-skus.md](../requirements/parent-child-pack-skus.md).

Problem: pack conversions (case/piece) and parent-child links must keep billing and stock consistent. Fields already existed; this slice hardens conversion at sale/stock, factor > 0, RBAC, and tenancy — no matrix/kit UI and no second catalog engine.

Done in this change (EXTEND, one slice):

- Scout: parent `Product.quantity` is already SoT; POS/checkout/returns already call `reduce_quantity` / `increase_quantity`, which convert child units by `conversion_factor`
- `conversion_factor` 0 / non-positive rejected on product create/update (field + serializer)
- Simple cycle reject on `parent_bulk_product` (self or loop)
- Pack-link mutations (`conversion_factor`, `parent_bulk_product`, `is_parent_bulk`) on create/update require `inventory.adjust` (owner implicit admin). Echo allowed. Bulk does not write these keys
- Tenancy unchanged: retailer-scoped get; parent pointer must be same shop

Out of scope: `StockMovement` cutover, matrix/kit UI, second catalog/pricing engine, FE, live `*.ordereasy.win`.
