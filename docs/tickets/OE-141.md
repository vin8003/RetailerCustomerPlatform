# OE-141 F-0032 — Damage and expiry write-off (thin slice)

Work snapshot. Durable: [damage-expiry-write-off.md](../requirements/damage-expiry-write-off.md).

Problem: spoilage, damage, and expiry write-offs had no first-class path. Expired qty stayed on `Product.quantity` after OE-136 forbade selling it.

Done in this change (EXTEND, one slice):

- `POST /api/products/<id>/write-off/` decreases `ProductBatch` / `Product` on-hand under `select_for_update` and writes `ProductInventoryLog` with reason `damage` / `expiry` / `spoilage`
- Expiry write-off requires a batch with `expiry_date < today` (same `is_expired()` as OE-136)
- Permission: existing `inventory.adjust` (no new catalog code)
- `GET /api/products/erp/inventory-ledger/?reason=` filters shrinkage for reports
- Tenancy: retailer-scoped get (404 deny)

Out of scope: `StockMovement` SoT cutover, separate damage vs expiry document types, FE / WMS, ATP engine, second inventory cache.
