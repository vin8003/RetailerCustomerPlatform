# OE-303 F follow-on — `is_available` on retailer search

Work snapshot. Durable: [search-is-available.md](../requirements/search-is-available.md).

List/detail serializers already expose top-level `Product.is_available`. `ProductSearchSerializer` Meta.fields omitted it after OE-287–300 (`brand_name` + `barcode` + `category_name` + `original_price` + `is_seasonal` + `product_group` + `discounted_price` + `is_featured` + `is_active`). This slice only returns top-level `is_available` on search.

POS `no_page` does not expose `is_available`. This slice does not add it there.

Public list/search querysets still filter `is_available=True`. Retailer search does not. This slice does not change those filters.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Search row includes `is_available` | List/detail only | **EXTEND** — same model value |
| False stays false | List/detail pass through | same on search (do not omit) |
| Auth/tenancy / public catalog | Shop-scoped retailer GET | unchanged; public search inherits via shared serializer |
| Availability write / admin / FE | Existing / invent | still out of scope |

## Done in this change (EXTEND, one slice)

- `ProductSearchSerializer` exposes `is_available` (`Product.is_available`) the same way list does (plain Meta field)
- Tests: search parity with list/detail for true and false, false echo on the shared serializer, public list + public search (public still omits unavailable SKUs), OE-287 `brand_name` + OE-290 `barcode` + OE-291 `category_name` + OE-293 `original_price` + OE-294 `is_seasonal` + OE-295 `product_group` + OE-298 `discounted_price` + OE-299 `is_featured` + OE-300 `is_active` light non-regression, auth denied, shop-scoped tenancy

Out of scope: availability write/admin, FE, POS `no_page` field add, search queryset change, OE-102, GST rebuild, inventory.adjust, timeline/OFD/khata/UPI/slots, pack write, merge, Jira Done, live `*.ordereasy.win`.
