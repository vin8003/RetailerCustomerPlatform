# OE-355 F follow-on — top-level `unit` on purchase-return line items

Work snapshot. Durable: [purchase-return-item-unit.md](../requirements/purchase-return-item-unit.md).

List/detail serializers already expose `Product.unit`. Purchase invoice lines echo it (OE-310). Sales-return items are OE-313 (`SalesReturnItemSerializer`). Purchase-return line items omitted it. This slice only: echo the same top-level `unit` on `PurchaseReturnItemSerializer` when `product.unit` exists.

Dummy / local only. Never `*.ordereasy.win`.

## Gap list (scout)

| AC | Before this slice | After |

## Done in this change (EXTEND, one slice)

- `PurchaseReturnItemSerializer` exposes read-only `unit` from `product.unit`
- List queryset prefetches items with `select_related('product')` so the echo does not add a product query
- Matches list/detail for the same SKU
- Tests: parity with list/detail, empty passthrough, write ignore, auth, tenancy, pack identity without conversion, no extra product query when product is already select_related
