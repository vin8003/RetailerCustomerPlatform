# OE-339 F follow-on — optional `hsn_code` on purchase-return line items

Work snapshot. Durable: [purchase-return-item-hsn.md](../requirements/purchase-return-item-hsn.md).

Purchase-return line items already echo `product` / `product_name`. They omitted optional HSN. Product has no `hsn_code` column on this stack — do not invent one. CTO overnight lock is this EXTEND only: echo `hsn_code` when the product attribute exists; otherwise `null`.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Purchase-return item includes optional `hsn_code` | Identity / qty / price only | **EXTEND** — `getattr(product, 'hsn_code', None)` |
| Missing field / null stays null | n/a | same (`null` / `""` passthrough) |
| Auth/tenancy | Shop-scoped purchase returns | unchanged |
| GST/HSN model / sales-return HSN | Missing | still out of scope |

## Done in this change (EXTEND, one slice)

- `PurchaseReturnItemSerializer` exposes read-only `hsn_code` via `product_hsn_code`
- Purchase-return queryset prefetches items with `select_related('product')` so the echo does not add a product query
- Tests: missing-field null on list/detail, attribute echo, null/empty passthrough, write ignore, auth, tenancy, no extra product query, SalesReturnItemSerializer / ProductSearchSerializer Meta stay without `hsn_code`

Out of scope: SalesReturnItemSerializer (OE-313), ProductSearchSerializer Meta, POS views, GST/HSN rebuild (KAN-57 / OE-57 / OE-102), purchase invoice serializers, cart, ledger, timeline/OFD/khata/UPI/slots, FE, merge, Jira Done, live `*.ordereasy.win`.
