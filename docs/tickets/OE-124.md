# OE-124 F-0027 — Product photo bulk import (thin slice)

Work snapshot. Durable: [product-photo-bulk-import.md](../requirements/product-photo-bulk-import.md).

Problem: retailers could add one photo per product (and scanner/Excel can carry a photo while creating items) but could not import a zip or csv+files of photos onto **existing** SKUs without a second media product.

Hard dep F-0017 ([OE-190](https://vin8003.atlassian.net/browse/OE-190)) is on the tip stack: catalog identity is `Product.id` + barcode (no SKU column). That is enough to attach.

Done in this change (EXTEND, one slice):

- `POST /api/products/upload/images/` accepts zip and/or csv+files
- Match by product id, barcode, additional barcodes, or batch barcode in the caller's shop
- Failed rows reported; the rest of the file still applies
- New file becomes `Product.image`; old file deleted; `image_url` and additional `is_primary` cleared
- `catalog.image` required (**403**, unchanged); anonymous cannot upload
- Tenancy: shop-scoped match (tenant B cannot attach to tenant A)
- Audit: `OrgAuditLog` `product_image`
- Tests: attach, fail-row, auth, replace-default, 403, tenancy
- SHIP nits: key-scoped catalog match (keys capped at 200, no silent result LIMIT); no `additional_images` prefetch on the match path; zip-without-CSV ignores dotted junk; same basename/stem last-wins; ambiguous barcode fails the row

Out of scope: second media engine, marketplace DAM, FE gallery redesign, Jira Done, live `*.ordereasy.win`.
