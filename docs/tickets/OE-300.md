# OE-300 F follow-on — `is_active` on retailer search

Work snapshot. Durable: [search-is-active.md](../requirements/search-is-active.md).

List/detail serializers already expose top-level `Product.is_active`. POS `no_page` already echoes it. `ProductSearchSerializer` Meta.fields omitted it after OE-287–299 (`brand_name` + `barcode` + `category_name` + `original_price` + `is_seasonal` + `product_group` + `discounted_price` + `is_featured`). This slice only returns top-level `is_active` on search.

Retailer and public search querysets still filter `is_active=True`. This slice does not change that filter.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Search row includes `is_active` | List/detail/POS only | **EXTEND** — same model value |
| False stays false | List/detail/POS pass through | same on search serializer (do not omit); HTTP search still excludes inactive SKUs |
| Auth/tenancy / public catalog | Shop-scoped retailer GET | unchanged; public search inherits via shared serializer |
| Active write / admin / FE | Existing / invent | still out of scope |

## Done in this change (EXTEND, one slice)
