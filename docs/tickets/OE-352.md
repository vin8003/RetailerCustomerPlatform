# OE-352 F follow-on — `brand_name` on purchase-return items

Work snapshot. Durable: [purchase-return-item-brand-name.md](../requirements/purchase-return-item-brand-name.md).

Product list/detail already expose `Product.brand.name` as `brand_name`. Purchase-return line items omitted it. This slice only echoes optional top-level `brand_name` on `PurchaseReturnItemSerializer` when the related product (and brand) exists.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Purchase-return item includes `brand_name` | `product_name` only | **EXTEND** — `product.brand.name` if product/brand exist |
| No brand / no product → `null` | n/a | same as list getter |
| Auth/tenancy / no N+1 | Shop-scoped GET | unchanged; prefetch `items__product__brand` |
| Sales-return items / search Meta / POS | Existing / invent | still out of scope |

## Done in this change (EXTEND, one slice)

- `PurchaseReturnItemSerializer` exposes `brand_name` via `product.brand.name` when product exists
- Purchase-return queryset prefetches `items` with `select_related('product', 'product__brand')`
- Tests: list/detail parity (two branded SKUs + unbranded), null brand passthrough, missing product → null, POST `brand_name` ignored, auth denied, shop-scoped tenancy, query budget, sales-return serializer lock

Out of scope: `SalesReturnItemSerializer` (OE-313), `ProductSearchSerializer` Meta, POS `products/views.py`, purchase invoice serializers, cart, ledger, FE, merge, Jira Done, live `*.ordereasy.win`.
