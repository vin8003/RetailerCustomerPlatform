# OE-106 F-0023 — App vs POS prices (thin slice)

Work snapshot. Durable: [app-vs-pos-prices.md](../requirements/app-vs-pos-prices.md).

Problem: the same SKU could not charge a different owned-app price than the store / POS price. Hard deps F-0022 (price lists) and F-0029 (ATP) are still Need Clarity; CTO ordered a thin EXTEND anyway.

Done in this change (EXTEND, one slice):

- `Product.app_price` nullable Decimal. Null falls back to store `Product.price`
- POS / retailer APIs keep store `price`; customer catalog and cart use the app list
- One ATP pool: existing `Product.quantity` / saleable (no channel stock)
- `catalog.price` required to change `app_price` (echo OK); **403** otherwise
- `OrgAuditLog` `channel_price` on `app_price` mutate
- Tenancy: retailer-scoped get (**404** deny)
- Marketplace channel: **not present** — documented as follow-on; no connector invented
- Reviewer block fix: `place_order` stamps cart/channel `unit_price` onto `OrderItem` (do not overwrite with store `Product.price`); retailer `search_products` passes request so POS search stays store channel
- Leftover payload rewrite: wishlist `product_price`, `group_variants[].price`, and `batches[].price` use the channel helper (no PriceList)

Out of scope: F-0022 PriceList / matrix UI, F-0029 ATP engine, marketplace connector, channel ATP split, Jira Done, live deploy.
