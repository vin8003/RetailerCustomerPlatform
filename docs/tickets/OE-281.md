# OE-281 D3 — Shop close-out from OFD

Work snapshot. Durable: [order-lifecycle.md](../07-KEY-FLOWS/order-lifecycle.md).

Problem: after OFD, retailer staff need a failed close-out with a required reason. OFD→delivered already existed. No rider engine (ADR-001 / OE-202 stay out of scope).

Done in this change (EXTEND):

- Inbox action `mark_failed` from `out_for_delivery` + `delivery_mode=delivery` → Order `cancelled`
- Required non-empty `reason` (or `notes`); writes `cancellation_reason` + `cancelled_by='retailer'`
- Reuses `restore_order_inventory` and OE-183 `order.status.cancelled` via `Order.update_status`
- Optional: `OrderDelivery.delivery_status='failed'` when a delivery row exists
- Status-path pairing: `PATCH orders/<id>/status/` OFD→`cancelled` also requires reason
- Perm/tenancy unchanged: retailer + `orders.update`; 403 missing perm; 404 cross-tenant
- Pickup `mark_delivered` / pickup_code gate unchanged

Out of scope: new Order status `failed`, `failure_reason`, `order.status.failed`, OE-202 rider/POD/reschedule, OE-58, Express, D4 filters, live `.win`.
