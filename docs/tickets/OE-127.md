# OE-127 F-0028 — Stock movements (thin slice)

Work snapshot. Durable: [inventory-adjust-permission.md](../requirements/inventory-adjust-permission.md).

Problem: cashiers/owners could free-form PATCH `Product.quantity` (and batch qty) via product update/bulk — AC4 gap. Full ledger SoT is OE-263 / OE-185.

Done in this change (EXTEND, one slice):

- Catalog v7 adds `inventory.adjust`; Admin bootstrap includes it; cashier stays empty
- Product update + bulk reject a **changed** `quantity` / `batches[].quantity` without that perm (**403**, stock unchanged). Echoing the current number is allowed so cashiers can still save price/name.
- Bulk compare uses the same `int()` write as apply (fractional echo cannot truncate without the perm) and runs after `select_for_update` (stale echo after a concurrent sale is 403).
- Owner (implicit admin) and staff granted `inventory.adjust` can still set quantity
- `ProductInventoryLog` Django admin is read-only
- Tenancy unchanged (retailer-scoped get); sale/purchase dual-write not rewritten

Out of scope: `StockMovement` ledger cutover, location WMS, FE rebuild, OE-263 dual-write, OE-185 locations.
