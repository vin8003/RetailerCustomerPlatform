# OE-146 F-0033 — Block negative stock (thin slice)

Work snapshot. Durable: [block-negative-stock.md](../requirements/block-negative-stock.md).

Problem: POS hardcoded `allow_negative=True` on `Product.reduce_quantity`, so a counter sale could drive on-hand below zero. Online `place_order` already defaulted to block.

Done in this change (EXTEND, one slice):

- POS `create_pos_order` deducts with `allow_negative=False` unless the caller already passes the existing flag (`allow_negative` is exactly `true`)
- `place_order` and order-modify sale deducts pass `allow_negative=False` explicitly
- Sale deducts `select_for_update` the Product (and ProductBatch when the caller has one) under the existing `atomic` before `reduce_quantity`. POS / place_order / modify use one `lock_for_sale` (sold SKUs + pack parents, pk ASC). Do not lock child-then-parent ad hoc.
- Purchase returns keep `allow_negative=True` (explicit override; not a sale path)
- Customer `place_order` body `allow_negative` is ignored
- Tenancy unchanged: retailer-scoped product get

Out of scope: org/location policy UI, correction tasks, FE settings, invent notify, new inventory service, OE-102, GST / #103, Jira Done, live deploy.
