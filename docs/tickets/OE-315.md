# OE-315 F follow-on — product identity on inventory-ledger rows

Work snapshot. Durable: [inventory-ledger-product-identity.md](../requirements/inventory-ledger-product-identity.md).

Product list already exposes `id` / `name` / `barcode` for a SKU. Inventory-ledger rows omitted those identity scalars, so shop-wide `?reason=` rows could not be matched to catalog list.

This slice only echoes list identity on `GET /api/products/erp/inventory-ledger/` in `products/api_erp_views.py`. Ledger `id` stays the log id. Product has no `sku` field — do not invent one.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Ledger row includes product identity matching list | Qty / reason / log id only | **EXTEND** — `product_id` / `product_name` / `barcode` |
| Null barcode stays null | n/a | same as list (`null` / `""`) |
| Auth/tenancy / no N+1 | Shop-scoped GET | unchanged; `select_related('product')` |
| POS / search / writes | Existing / invent | still out of scope |

## Done in this change (EXTEND, one slice)

- Ledger row payload includes `product_id` (list `id`), `product_name` (list `name`), `barcode` (list `barcode`)
- Tests: list parity (two SKUs), null/empty barcode passthrough, `product_id` filter, auth denied, shop-scoped tenancy, query budget

Out of scope: POS `products/views.py`, search Meta, cart, returns, purchase invoice, customers, orders, inventory.adjust, timeline/OFD/khata/UPI/slots, pack write, merge, Jira Done, live `*.ordereasy.win`.
