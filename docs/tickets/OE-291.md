# OE-291 F follow-on — `category_name` on retailer search

Work snapshot. Durable: [search-category-name.md](../requirements/search-category-name.md).

List/detail serializers already expose `Product.category.name` as `category_name`. POS `no_page` already echoes it. `ProductSearchSerializer` Meta.fields omitted it after OE-287/290 (`brand_name` + `barcode`). This slice only returns top-level `category_name` on search.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Search row includes `category_name` | List/detail/POS only | **EXTEND** — same model value |
| No category → list getter sentinel | List/detail `null`; POS `Uncategorized` | search mirrors **list** (`null`) |
| Auth/tenancy / public catalog | Shop-scoped retailer GET | unchanged; public search inherits via shared serializer |
| Category write / category CRUD | Existing | still out of scope |

## Done in this change (EXTEND, one slice)

- `ProductSearchSerializer` exposes `category_name` via the same getter as list (`None` when unset)
- Retailer + public search querysets `select_related('category')` (no per-row category PK lookups)
- Tests: search parity with list/detail/POS, null category mirrors list, public list + public search, OE-287 `brand_name` + OE-290 `barcode` light non-regression, auth denied, category join

Out of scope: category CRUD, POS Uncategorized rewrite, FE, OE-102, GST rebuild, inventory.adjust, timeline/OFD/khata/UPI/slots, pack write, merge, Jira Done, live `*.ordereasy.win`.
