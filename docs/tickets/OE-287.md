# OE-287 F follow-on — `brand_name` on search + POS no_page

Work snapshot. Durable: [search-pos-brand-name.md](../requirements/search-pos-brand-name.md).

List/detail serializers already expose `Product.brand.name` as `brand_name`. Search Meta.fields and the POS `no_page` hand-built row omitted it. POS `select_related` skipped `brand`. CTO overnight lock is this EXTEND only: echo the same top-level `brand_name` on retailer search and POS `no_page`.

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Search row includes `brand_name` | List/detail only | **EXTEND** — same model value |
| POS `no_page` row includes `brand_name` | List/detail only | **EXTEND** — same model value |
| No brand → `null` | List getter returns `None` | same on search + POS |
| Auth/tenancy / public catalog | Shop-scoped retailer GET | unchanged |
| Brand write APIs | Existing | still out of scope |

## Done in this change (EXTEND, one slice)

- `ProductSearchSerializer` exposes `brand_name` via the same getter as list
- POS `no_page` dict includes `brand_name` (`p.brand.name if p.brand else None`)
- POS + retailer search `select_related` include `brand`; public search gets the same join (shared serializer)
- Tests: search/POS parity with list/detail, null brand, auth, tenancy, public list + public search, brand join (no per-row lookup), OE-286 unit + OE-285 pack identity non-regression

Out of scope: brand CRUD, public catalog invent, inventory.adjust, timeline/OFD/khata/UPI/slots, pack write, FE, merge, Jira Done, live `*.ordereasy.win`.
