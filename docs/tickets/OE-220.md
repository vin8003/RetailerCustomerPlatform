# OE-220 F-0107 — Shop rewards and OTP redeem (thin slice)

Work snapshot. Durable: [shop-rewards-otp-redeem.md](../requirements/shop-rewards-otp-redeem.md).

Problem: earn/redeem shop rewards with OTP burn when enabled. One wallet per customer+program. EXTEND `RetailerRewardConfig` / `Order.points_earned` / `discount_from_points`. No second engine, no `restaurant_points`.

## Scout (mandatory)

### 1. Config / wallet / ledger

| Piece | Where | Status |
|-------|--------|--------|
| `RetailerRewardConfig` | `retailers/models.py` — OneToOne per location. `earning_type`, `loyalty_earning_value`, `loyalty_min_order_value`, redemption caps, `conversion_rate`, referral flags. **No OTP mode field.** | PARTIAL |
| Wallet | `CustomerLoyalty` unique `(customer, retailer)` — one balance, not org-wide | EXISTING |
| Ledger | `LoyaltyTransaction` earn/redeem/refund/expire | EXISTING |
| `restaurant_points` | Absent. Do not add. | SKIP |

### 2. Order fields and finalize writes

| Piece | Where | Status |
|-------|--------|--------|
| `Order.points_earned` / `discount_from_points` / `points_redeemed` | `orders/models.py` | EXISTING |
| App checkout redeem | `OrderCreateSerializer` `use_reward_points` — burns wallet, sets discount. **No OTP.** | EXISTING (no OTP) |
| App earn | `Order.award_loyalty_points()` on `delivered` | EXISTING |
| POS finalize earn | `create_pos_order` creates `delivered` then `order.award_loyalty_points()` | EXISTING |
| POS finalize redeem | POS does **not** burn points or set `discount_from_points` | MISSING (FE+payment math; follow-on) |

### 3. Redeem / OTP paths

| Piece | Status |
|-------|--------|
| Auth SMS OTP (`OTPVerification`, `generate_otp`, `send_sms_otp`) | EXISTING — login only |
| Loyalty redeem OTP | MISSING |
| F-0007 operation password / manager PIN | **Not in tree** — do not invent; OTP is the sensitive gate |
| OE-212 phone lookup | EXISTING on #94 tip — staff can find the customer |

### 4. Gap list vs AC

| AC | Status |
|----|--------|
| Qualifying sale earns points per program | **EXISTING / PARTIAL** — POS finalize + delivered use `RetailerRewardConfig` into `CustomerLoyalty`. Not idempotent if `award_loyalty_points` is called twice. |
| Redeem without OTP fails when OTP mode on | **MISSING** — checkout redeems with no OTP; config has no OTP flag |
| Chain-wide A earn / B burn | **MISSING / follow-on** — wallet is per location. Not trivial; do not invent org-vs-location policy |
| Restaurant visit same wallet | **MISSING / follow-on** — no visit-earn hook; do not invent `restaurant_points` |
| Unauthorized → 403 unchanged | **EXISTING** on config (retailer-only); **MISSING** on a redeem endpoint (none exists) |
| Cross-tenant deny | **EXISTING** on config (own profile only); **MISSING** on redeem (none exists) |

### 5. Chosen slice

**B — OTP redeem.** Earn-on-sale is already wired on POS finalize and app delivery; OTP burn is the AC that currently cannot pass.

Not blocked: reuse existing SMS OTP helpers (no provider choice). Program scope stays customer+retailer. Earn formula already lives on `RetailerRewardConfig` (`loyalty_earning_value` / `earning_type`); unused `cashback_percentage` left alone.

## This PR (slice B only)

- `RetailerRewardConfig.otp_required_for_redeem`
- Loyalty redeem OTP (not login OTP) to the customer's registered mobile
- App checkout: `use_reward_points` without OTP fails when mode is on
- Checkout validate `peek_redeem_otp` locks the OTP row before incrementing `attempts` (create transaction unchanged)
- Staff redeem endpoint on a pending order: without OTP → fail; valid OTP burns + `discount_from_points`
- 403 / tenancy; OTP secret not returned or logged
- F-0007 PIN: absent — noted, not invented

## Out of this PR

Chain policy engine, restaurant visit earn, POS redeem UI / POS checkout burn, campaigns, second wallet, Jira Done, live `*.ordereasy.win`.
