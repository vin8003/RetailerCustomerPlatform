# OE-314 F follow-on — `brand_name` on cart items

Work snapshot. Durable: [cart-brand-name.md](../requirements/cart-brand-name.md).

List/detail serializers already expose `Product.brand.name` as `brand_name`. Cart line items omitted the top-level key. This slice only echoes the same value on `CartItemSerializer` (null stays null).

## Gap list (scout)

| AC | Before this slice | After |
|----|-------------------|--------|
| Cart item includes `brand_name` | List/detail only | **EXTEND** — same model value |
| No brand → `null` | List getter returns `None` | same on cart items (do not omit) |
| Auth/tenancy | Customer-only cart; shop-scoped | unchanged |
| Brand write / FE ProductCard | Existing / OE-316 | still out of scope |

## Done in this change (EXTEND, one slice)

- `CartItemSerializer` exposes `brand_name` (`product.brand.name`)
- `CartSerializer.to_representation` prefetches items with `select_related('product', 'product__brand')` so the echo is one join, not per-row
- Tests: cart parity with list/detail/public catalog, null brand, serializer echo, auth denied, customer/shop tenancy, add-to-cart response, brand join (no per-row lookup)

Out of scope: barcode on cart (OE-326), FE ProductCard (OE-316), search Meta, POS, checkout/UPI/slots/khata, merge, Jira Done, live `*.ordereasy.win`.
